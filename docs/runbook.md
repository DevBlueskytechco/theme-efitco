# Runbook · DevOps · khung, điền sprint 1

Mỗi sự cố: Triệu chứng → Xác nhận → Xử lý → Rollback → Phòng ngừa.
1. Push preview fail vì theme check — `shopify theme check --output json --fail-level error > check.json; scripts/shopify-cli.sh check-report check.json` local (in file:dòng:cột từ 1); sửa Liquid, không thêm override.
2. Preview trắng vì settings_data.json tham chiếu resource không có — kiểm `config/settings_data.json`, bỏ default resource.
3. Lighthouse tụt dưới ngưỡng — so report với sprint trước; thủ phạm thường: ảnh hero, font, JS mới; xem ADR 0003.
4. hoa-qua-nhap-khau (efitco-ai-dev) hết slot theme (20) — `shopify theme list --json`, liệt kê `ai-*` > 7 ngày, người xoá.
5. CLI mất auth trong CI — xoay `SHOPIFY_CLI_THEME_TOKEN` (Theme Access app), cập nhật secret.
6. Nâng cấp theme đã sửa trong Canvas — upload zip mới thành theme mới → `scripts/diff-settings.sh` → merchant chuyển theme trong Canvas; theme cũ giữ lại để rollback.
7. Shopify CLI lệch phiên bản / CLI 5.x đổi JSON (ES1-T32) — Triệu chứng: `assert-version` fail; `theme-id`/`push-result`/`check-report` báo "không phải JSON" hoặc thiếu id. Xác nhận: `scripts/shopify-cli.sh assert-version`, `bash scripts/shopify-cli.test.sh`, log job `cli5-canary`. Xử lý: cài bản ghim `npm i -g "@shopify/cli@$(scripts/shopify-cli.sh pinned)"`; schema mới thì thêm fixture vào `scripts/shopify-cli.test.sh` rồi sửa jq trong `scripts/shopify-cli.sh`. Push `status: partial` = lỗi nội dung theme: sửa file theo `::error file=` trong log, không thử lại. Rollback: revert `PINNED_CLI` về 4.9.5. Phòng ngừa: chỉ nâng khi `cli5-canary` xanh nhiều PR liên tiếp, đổi `PINNED_CLI` trong PR riêng; `cli5-canary` không phải required check.
8. Theme preview `ai-*` thành live (ES1-T162) — Triệu chứng: job `preview` dừng với `::error::theme 'ai-...' (id ...) có role live`, hoặc annotation `live theme đang là preview`. Xác nhận: `shopify theme list --json`, xem role theo id trong log. Xử lý: agent/CI không push, không xoá, không đổi theme đó; CTO đưa theme đúng trở lại live rồi chạy lại job `preview`. Rollback: không có, script không ghi gì lên store ở nhánh này. Phòng ngừa: `scripts/preview-push.sh` đọc role trước mỗi lần push; `live-theme-warn` chạy ở mọi PR.
9. Run `store-tests` bị huỷ khi chờ store (ES1-T162) — Triệu chứng: check `lighthouse`, `e2e` đỏ với `không chạy (store-tests: cancelled)`, PR không có lỗi test. Nguyên nhân: group `store-hoa-qua-e2e` giữ 1 chạy + 1 chờ; run mới vào hàng thay run đang chờ. Xử lý: chạy lại run đó khi group rảnh, không phải sửa code. Rollback: bỏ `concurrency` ở job `store-tests` trong `.github/workflows/ci.yml`. Phòng ngừa: mở PR lần lượt khi có từ 3 PR cần dùng store cùng lúc. PR chưa rebase lên commit có group này thì chưa vào hàng.
10. Quá 2 PR cùng chờ store tests (ES1-T177, plan ES1-T169 D5, ES1-T165 phương án A) — Triệu chứng: từ PR thứ 3 cùng mở, run đang chờ bị huỷ như mục 9. Xác nhận: tab Actions lọc job `store-tests`, đếm run `in_progress` + `queued` (hoặc `gh run list --workflow CI --status queued`). Xử lý: tối đa 2 PR trong CI cùng lúc (1 chạy + 1 chờ); PR thứ 3 chờ 1 PR xong mới push hoặc chạy lại, không thêm cơ chế xếp hàng, không thêm token. Rollback: không có, đây là quy ước. Phòng ngừa: người điều phối mở PR theo lượt; mỗi run store tests (lhci 4 URL × 3 lần × 2 máy + đo JS 6 URL × 2 máy + e2e 4 shard) giữ store khoảng 1 lần chạy, xem thời gian thực ở run gần nhất.
11. Ngân sách JS theo URL đỏ (ES1-T177, ADR 0006, 0010) — Triệu chứng: check `lighthouse` đỏ, bước `Ngân sách JS theo URL` có `::error title=Ngân sách JS <máy> <url>::JS tải sẵn X B > trần 40960 B` hoặc `JS sau cuộn X B > trần 65536 B`; bảng `[js-budget]` in từng file (lúc, transfer, chưa nén, nguồn). Xác nhận: `STORE_ORIGIN=https://hoa-qua-nhap-khau.myshopify.com THEME_ID=<preview id> STORE_PASSWORD=... node scripts/js-budget.mjs` (đọc storefront, ghi 1 giỏ tạm của phiên; không ghi theme); logic: `node scripts/js-budget.test.mjs`. Xử lý: file mới nạp ở `tải sẵn` mà ADR 0010 xếp nạp lười thì chuyển sang `lazy-module`; file vượt trần riêng thì giảm byte; không nâng trần (env chỉ hạ được). Lỗi `đo nhầm theme`: preview chưa áp, chạy lại job `preview`. `::error title=Lỗi store dev, không phải lỗi code` (429, Cloudflare, 5xx; script thoát 3, có `[js-budget] số_lần_429`): chạy lại khi store hết chặn, không sửa code. Chứng minh cổng đỏ (DoD ES1-T177): đặt `gh variable set JS_BUDGET_SCROLL_MAX --body 1000` (và/hoặc `JS_BUDGET_PRELOAD_MAX`), chạy lại run của PR, chép log có `[TRẦN GIẢ ...]` vào PR, rồi `gh variable delete JS_BUDGET_SCROLL_MAX` ngay (var áp cho mọi PR đang chạy). Rollback: xoá 3 bước JS trong job `lighthouse` của `.github/workflows/store-tests.yml`. Phòng ngừa: PR BE ghi phép cộng theo trang (ADR 0010); khi `RUN_STORE_TESTS=false` bước này KHÔNG chạy ở PR (check `lighthouse` pass có cảnh báo CHƯA CHẠY), chạy tay `gh workflow run CI --ref <nhánh>`.
12. `assets/base.css` gzip vượt 49 152 B (ES1-T310 #1) — Triệu chứng: check `theme-check` đỏ ở bước `base.css gzip ≤ 49 152 B`. Xác nhận: `gzip -c assets/base.css | wc -c`. Xử lý: task FE xoá CSS cũ của phần nó thay; CSS chết rà ở TE-10-R2-FE3; không tách file khi chưa có ADR (AGENTS.md giữ 1 file). Rollback: xoá bước đó trong job `theme-check` của `.github/workflows/ci.yml`. Phòng ngừa: PR FE ghi số gzip trước/sau.
